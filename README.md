# 视频解析插件（cn.ucbk.video）

一个面向 NapCat / OneBot 宿主的 QQ 视频解析插件。

在群聊或私聊中发送抖音、哔哩哔哩（B站）、小红书、快手、今日头条、微博、皮皮搞笑或皮皮虾链接，插件会自动识别平台并解析媒体信息：视频作品先发送一条描述卡片，再发送视频；如果 QQ 拒收视频，则自动降级为无水印直链。抖音图文作品会按批发送原图，并在最后补充作品说明。

## 功能特性

- 支持抖音、哔哩哔哩、小红书、快手、今日头条、微博、皮皮搞笑、皮皮虾、即梦 AI、豆包 AI 共 10 个平台
- 支持抖音图文作品与小红书图文笔记
- 支持抖音实况（LivePhoto）作品：静态图之外再补发那段短视频
- 支持平台短链：`v.douyin.com`、`b23.tv`、`xhslink.com`、`v.kuaishou.com`、`t.cn`
- 默认粘贴链接即可触发，也可以切换为「仅指令触发」
- 视频描述与视频分开发送，避免部分 NapCat 版本丢失文本段
- 抖音图文按每批 3 张图片分开发送，单批失败会自动逐张重试
- 支持视频时长上限、重复冷却和解析结果缓存
- 清晰度可在插件配置里选（1080P / 720P / 480P / 360P），三个平台通用，取不超过所选档的最高可用；默认「自动最高」
- B站从所选档位起按 1080P → 720P → 480P → 360P 逐级降级，所选档不可用时自动退档
- 解析结果包含标题、作者、时长、清晰度、互动数据和作品简介
- QQ 拒收视频时自动补发无水印直链，不静默失败
- **所有平台都是自己发请求、自己解析，不经过任何第三方中转服务**
- 不依赖第三方 Python 库，仅使用宿主 SDK 与 Python 标准库

## 权限与出网

插件声明以下能力：

| 能力 | 用途 | 风险说明 |
| --- | --- | --- |
| `msg.send` | 向群聊或私聊发送文字、图片和视频 | 中风险 |
| `http.outbound` | 请求平台页面和接口，解析媒体地址 | 高风险 |

启用插件前，需要在宿主面板中批准 `http.outbound`。如果没有批准：

- 插件可以正常安装；
- 发送链接时不会进行平台请求；
- 机器人会提示未获批访问外网；
- 宿主动作审计中可以看到被拒绝的原因。

插件只请求 `manifest.json` 中声明的域名：

- 抖音：`www.iesdouyin.com`、`v.douyin.com`、`m.douyin.com`
- B站：`api.bilibili.com`、`b23.tv`
- 小红书：`www.xiaohongshu.com`、`xhslink.com`

图片和视频的最终下载由 NapCat 负责，不由本插件代为下载保存。

## 配置项

配置由 `manifest.json` 中的 `config_schema` 定义，具体配置界面以宿主实际显示为准。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 生效范围 | 群聊与私聊 | 可改为仅群聊或仅私聊 |
| 触发方式 | 粘贴链接即解析 | 也可改为仅指令触发 |
| 指令触发词 | 解析,视频解析 | 仅指令模式生效，支持中文逗号、英文逗号和分号 |
| 回复方式 | 发送视频 | 改为只发链接时，仅发送文字卡片和直链 |
| 视频清晰度 | 自动最高 | 抖音 / B站 / 小红书通用，可选 1080P / 720P / 480P / 360P；取不超过所选档的最高可用，所选档没有就自动退档 |
| 直发视频的时长上限 | 0 | 0 或留空表示不限时长 |
| 同一链接重复解析冷却 | 15 秒 | 同群重复贴同一条链接会被忽略；0 或留空取默认，-1 关闭 |
| 解析结果缓存时间 | 600 秒 | 同一链接在缓存有效期内直接复用；0 或留空取默认，-1 关闭 |
| 抖音 Cookie | 空 | 抖音触发风控或解析失败时填写 |
| B站 Cookie | 空 | 用于尝试获取更高清晰度 |
| 小红书 Cookie | 空 | 小红书网页解析需要登录 Cookie |
| 微博 Cookie | 空 | **微博必填**，不填会被跳到新浪访客系统而解析失败 |
| 快手 Cookie | 空 | 可选，遇到风控时填写能提高成功率 |

### 配置行为说明

- 数字配置有安全范围，非法值或超出范围的值会自动回退或截断。
- `max_duration` 的最大值为 3600 秒。
- 图文作品不设发送张数上限；为避免 NapCat 丢图，图片仍按每批 3 张分开发送。
- 冷却时间最大为 300 秒，缓存时间最大为 3600 秒。
- `0` 和空值在时长、冷却、缓存配置中代表使用默认行为，不代表关闭。
- 需要关闭冷却或缓存时填写 `-1`。

## 支持平台与解析方式

### 抖音

插件优先请求**免 Cookie 详情接口** `api.amemv.com/aweme/v1/aweme/detail/`，直接拿到结构化的作品数据；接口不可用时再退回 `iesdouyin` 分享页内嵌的 `window._ROUTER_DATA`，不需要实现抖音签名算法。

- 视频作品：按 `bitRate` 码率降序挑选最高画质档位，地址优先用 `v3-web` 域名；
- 原画：取 `play_addr.uri`（vid）拼出播放地址，跟随 302 拿到真正的无水印文件；
- 图文作品：提取全部原图地址，按每批 3 张分批发送，不限张数；
- 分享页前几次可能只返回空壳页面，插件会自动重试，最多请求 3 次；
- 抖音没有独立标题时，会使用文案第一行作为标题；
- 抖音 Cookie 可用于提高触发风控时的解析成功率。

### 哔哩哔哩（B站）

插件使用 B站 Web 接口：

1. 调用 `x/web-interface/view` 获取标题、封面、作者、时长和互动数据；
2. 调用 `x/player/playurl` 获取单文件 MP4 播放地址；
3. 按 1080P60、1080P+、1080P、720P60、720P、480P、360P 顺序逐级尝试；
4. 视频被 QQ 拒收时，自动换成中机房 CDN 域名重试一次，避开区域边缘节点的防盗链。

使用 `platform=html5` 获取带音轨的单文件视频，因此不需要 ffmpeg 合流。支持 BV 号、av 号、多 P 视频和 `b23.tv` 短链。

### 小红书

小红书没有在本插件中使用公开 API，而是读取笔记页面内嵌的 `window.__INITIAL_STATE__`：

- 视频笔记：读取 `media.stream` 中的播放地址，页面给了分辨率元数据时按配置的清晰度挑选；
- 图文笔记：读取 `imageList` 中的原图地址；
- 图片清晰度用小红书的 `imageView2` 处理参数控制（`w/0` 为原图宽度，填具体数值即限宽压缩）；
- 页面中的 JavaScript `undefined` 会先转换为 JSON 可识别的 `null`；
- 未登录访问通常会跳转到登录页或 404 页面，因此必须配置有效 Cookie。

小红书 Cookie 至少应包含 `a1` 和 `web_session`。Cookie 过期后，需要重新从浏览器开发者工具中复制。

### 皮皮搞笑

分享链接里带 `pid` 与 `mid`，插件 POST 到官方分享接口 `h5.pipigx.com/ppapi/share/fetch_content` 取作品数据，包含文案、视频地址与封面。

### 快手

分享链接跳到作品页后，插件从页面内嵌数据里取作品信息：

1. 优先解析页面里的 `window.INIT_STATE`，取作品条目（顶层键以 `tusjoh` 开头）里的 `photo` 节点；
2. `INIT_STATE` 缺失时用 `window.__APOLLO_STATE__` 兜底；
3. 视频取 `photo.srcNoMark`（无水印地址），图集取 `photo.ext_params.atlas.list`；
4. 同时带出标题、作者、点赞数与封面。

遇到风控时可以在配置里填「快手 Cookie」提高成功率。

### 今日头条

分享链接跳到移动端作品页 `m.toutiao.com/video/{id}/`，页面里有一段 URL 编码的
`RENDER_DATA` JSON，解码后从 `articleInfo` 取标题、作者、封面、时长与互动数据。

播放地址要两步才能拿到：先把 `playAuthTokenV2` 做 base64 解码得到 `GetPlayInfoToken`，
再请求字节跳动的 VOD 调度接口 `vod.bytedanceapi.com/?{token}`，
返回的 `Result.Data.PlayInfoList[]` 里 `MainPlayUrl` 就是播放地址，插件自动取最高档。

> 桌面端 `www.toutiao.com/video/` 页面现在是 JavaScript 壳，取不到内嵌数据，
> 所以插件固定走移动端页面。

### 微博

分享链接里带作品编号（`fid`），插件 POST 到微博组件接口
`weibo.com/tv/api/component?page=/tv/show/{fid}` 取作品信息，
按 `2K > 1080P > 720P > 480P > 360P` 的顺序挑最清晰的一档。

**微博现在要求登录态**：不带 Cookie 会被跳到新浪访客系统（访客 Cookie 需要浏览器执行 JS 生成，
纯出网请求拿不到），所以必须在插件配置里填「微博 Cookie」。

视频地址用微博返回的原始地址，不走任何第三方代理；原始地址需要 Referer 头，
NapCat 拉取时被拒的话会退到备用地址。

### 皮皮下

分享链接跳到作品页后能从地址里拿到作品编号（`cell_id`），插件再调官方分享接口
`h5.pipix.com/bds/cell/cell_h5_comment/` 取数据，
从 `cell_comments[1].comment_info.item` 里取视频地址、图集、作者与封面。

### 即梦 AI

分享链接里带 `item_id`，插件 POST 到 `jimeng.jianying.com/mweb/v1/get_item_info` 取作品数据。视频地址优先取 `transcoded.origin`，即**原画**文件。

### 豆包 AI

分享链接里带 `share_id` 与 `video_id`，插件 POST 到 `www.doubao.com/creativity/share/get_video_share_info` 取作品数据。接口字段名各版本不完全一致，插件用深度检索兜底取播放地址与封面。

## 工作流程

1. 收到群聊或私聊消息；
2. 从文本中识别支持的平台链接；
3. 如果是短链，手动跟随跳转并限制跳转次数；
4. 检查 `msg.send` 和 `http.outbound` 权限；
5. 检查同一会话的重复冷却；
6. 查询解析缓存，命中时直接复用结果；
7. 未命中缓存时调用对应平台解析器；
8. 发送描述卡片；
9. 视频作品发送视频，失败时补发直链；
10. 图文作品按批发送全部图片，最后发送描述；
11. 将解析结果写入短期缓存。

## 回复示例

### 视频作品

```text
【哔哩哔哩】这可能是今年最好看的城市纪录片
@某UP主 · 时长 21:05 · 1080P · 第一集：起点
播放 123.4万 · 弹幕 2.1万 · 点赞 8.6万 · 收藏 3.2万

拍摄历时三个月，走过 12 座城市。
```

上面的描述会单独发送，视频随后作为另一条消息发送。

### 图文作品

图片按每批 3 张发送，最后再发送类似下面的说明：

```text
【抖音】图文作品标题
@作者 · 点赞 1.2万 · 评论 345

作品简介……
```

如果个别图片发送失败，说明中会显示成功数量，并附上原始作品链接。

## 故障排查

### 机器人没有反应

1. 确认插件已启用；
2. 确认当前机器人已勾选为生效机器人；
3. 确认消息中包含支持的平台链接；
4. 确认已批准 `msg.send` 和 `http.outbound`；
5. 查看宿主动作审计和插件日志。

### 提示未获批访问外网

在宿主插件审核或能力管理页面单独批准 `http.outbound`，保存后重新发送链接。

### 宿主日志出现「重启插件子进程，原因=事件处理超时」

宿主对单个事件的处理有时间上限（默认 10 秒，由宿主配置 `PLUGIN_EVENT_TIMEOUT` 控制）。
本插件已经把**整条流水线（解析 + 发送）**都放到后台执行：事件收到链接后立刻结束，
解析、出网请求、发视频、发图都在后台慢慢跑，正常情况下不会再触发超时。

一旦事件超时，宿主会重启插件子进程，后台正在发的内容会丢在半路，
表现就是「10 张图只到了 9 张」或者「视频没发出来」。若仍出现：

- 调大宿主的 `PLUGIN_EVENT_TIMEOUT`（例如 30 秒），给网络波动留余量；
- 填好各平台 Cookie，减少重试与风控带来的额外请求。

### 抖音解析失败

- 确认链接来自抖音 App 或 `www.douyin.com`；
- 触发风控时填写抖音 Cookie；
- 检查宿主是否支持 `max_chars`；
- 检查事件超时是否过短。

### 微博提示「要求登录后才能解析」

微博现在要求登录态：不带 Cookie 会被跳到新浪访客系统（访客 Cookie 需要浏览器执行 JS 生成，
纯出网请求拿不到）。在插件配置里填好「微博 Cookie」再试。

### 快手解析失败

- 确认链接是快手 App 分享出来的完整链接；
- 页面结构变动时会出现「没有找到作品数据」，可尝试填写快手 Cookie 后重试。

### 今日头条解析失败

- 分享链接可能已失效，插件会提示「分享链接可能已失效，请重新复制」；
- 桌面端页面是 JavaScript 壳，插件固定走移动端页面，无需用户干预。

### 皮皮下解析失败

- 分享链接里要带作品编号（`cell_id`），否则会提示「没有从链接里识别出作品编号」；
- 作品已删除时接口会返回参数错误，此时提示里会带接口给的原因。

### B站没有视频或清晰度较低

- 视频可能已删除、仅限登录可见或需要大会员；
- 填写 B站 Cookie 后重试；
- 插件会自动逐级尝试较低清晰度；
- NapCat 下载 B站 CDN 地址时应使用正常的客户端请求头。

### 小红书解析失败

- 小红书必须填写有效 Cookie；
- Cookie 至少应包含 `a1` 和 `web_session`；
- Cookie 过期后重新复制；
- 如果页面返回 404 或 500，优先检查 Cookie 是否有效；
- 如果提示页面数据被截断，检查宿主是否允许 `max_chars=200000`。

### 图文图片没有发全

插件会将图片按每批 3 张分开发送，单批失败后自动逐张重试。仍有图片缺失时：

- 检查宿主日志中是否有发送失败记录；
- 确认 QQ / NapCat 对图片 URL 可以正常访问；
- 点击最后一条说明中的原始作品链接查看全部图片。
