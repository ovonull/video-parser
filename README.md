# 视频解析插件（cn.ucbk.video）

一个面向 NapCat / OneBot 宿主的 QQ 视频解析插件，以 **AI 工具**的形式提供。

群里贴抖音、哔哩哔哩（B站）、小红书、快手、今日头条、微博、皮皮搞笑、皮皮虾、即梦 AI 或豆包 AI 的分享链接时，由 AI 调用 `parse_video_link` 读取真实的标题、作者、时长、互动数据与简介，再按机器人人设组织回复；视频或原图由系统紧跟回复一起发出。

插件**不监听消息、不抢占消息、不主动发送描述卡片、不补直链**。这条消息的回复主体始终是 AI，运行记录的「Agent 调用步骤」里能看到这次插件调用。

## 工作方式

```text
群友贴链接
  → 宿主把消息交给 AI（不再因插件声明接管而让位）
  → AI 调用 parse_video_link，插件出网解析平台
  → 工具返回作品信息 + attachments（视频/图片）
  → AI 生成一句话回复
  → 宿主发出正文，随后补发 attachments 里的媒体
```

媒体补发失败只记日志：发不出来就是发不出来，不会退化成一条直链，也不会把已经发出的正文改判成失败。

## 开启条件

1. 在插件中心安装并启用本插件，批准 `http.outbound` 能力；
2. 机器人开启 AI 回复。消息里带链接时，宿主会自动把智能体与「插件工具」接进本轮的 Agent 调用链，不需要额外开关；
3. 模型渠道需为 OpenAI 兼容协议，否则该渠道不支持工具调用，模型只能按普通对话回复。

## 能力声明

| 能力 | 用途 | 风险说明 |
| --- | --- | --- |
| `http.outbound` | 请求平台页面和接口，解析媒体地址 | 高风险，需管理员手动批准 |

本插件**不申请** `msg.send` 与 `llm.generate`：发消息和生成回复都由宿主/AI 完成。

未批准 `http.outbound` 时工具会返回一段中文说明，AI 据此如实告诉用户暂时解析不了，不会凭空编造视频内容。

## 配置项

| 配置 | 说明 |
| --- | --- |
| 是否随回复发送视频 | 选「不发送视频」时工具只返回文字信息，不排队媒体 |
| 视频清晰度 | 1080P / 720P / 480P / 360P，取不超过所选档的最高可用；默认「自动最高」 |
| 随回复发送视频的时长上限 | 秒；0 或留空为不限时长，超时长上限时只回文字 |
| 解析结果缓存时间 | 秒；0 或留空默认 600，-1 关闭 |
| 抖音 / B站 / 豆包 / 小红书 / 微博 / 快手 Cookie | 按需填写；小红书与微博网页端要求登录，抖音与快手遇到风控时可补 |

从旧版本升级时，配置里残留的「触发方式」「重复冷却」「AI 补一句评价」等项会被忽略。旧值「只发链接」按「不发送视频」处理。

## 支持平台

抖音、哔哩哔哩、小红书、快手、今日头条、微博、皮皮搞笑、皮皮虾、即梦 AI、豆包 AI。

支持平台短链：`v.douyin.com`、`b23.tv`、`xhslink.com`、`v.kuaishou.com`、`t.cn`。抖音图文作品与小红书图文笔记返回全部原图（一次最多排队 9 张），抖音实况作品还会带上那段短视频。

所有平台都是自己发请求、自己解析，不经过任何第三方中转服务；图片与视频由 NapCat 自行拉取。

## 常见问题

**链接贴进群里没反应**：确认机器人 AI 已开启、插件已启用且 `http.outbound` 已批准；再到运行记录里看有没有「插件刚在该会话回复过」这类让位记录——装了旧版本自动抢答的插件时会命中它，升级到本版本即可。

**回复有了但视频没到**：媒体是单独补发的，QQ 拒收大文件或格式不支持时只会记日志，不会补直链。可以调低清晰度或缩短时长上限再试。

**Agent 调用步骤里看不到插件调用**：说明这一轮没走工具循环。确认机器人打开了「智能体」，且消息里确实带了受支持平台的链接。
