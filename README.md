# 视频解析插件（cn.ucbk.video）

群聊或私聊里贴抖音、B站、小红书链接，机器人先回一条**描述卡片**（标题、作者、时长、互动数据、作品简介），紧接着把**视频**发出来；只有 QQ 真的拒收（体积过大、格式不支持）时才补一条无水印直链。默认不限时长。

## 能力与出网

| 项 | 内容 |
| --- | --- |
| 能力 | `msg.send`（中风险）、`http.outbound`（**高风险**） |
| 出网域名 | `www.iesdouyin.com`、`v.douyin.com`、`m.douyin.com`、`api.bilibili.com`、`b23.tv`、`www.xiaohongshu.com`、`xhslink.com` |
| 依赖 | 无第三方库，只用宿主 SDK 与标准库 |

`http.outbound` 是高风控能力，**审核时必须由管理员在面板上单独勾选**才会写入「已批准能力」；漏勾时插件会正常装但一发链接就回「未获批访问外网」，动作审计里能看到拒绝原因。

## 打包与安装

```bash
python plugins/pack.py video-parser
# 生成 plugins/dist/cn.ucbk.video-1.1.3.zip
```

1. 插件市场 → 提交压缩包，上传上面的 zip；
2. 插件审核 → 审核通过（记得勾选 `http.outbound`）→ 上架；
3. 插件市场 → 安装，勾选生效机器人，填配置后**手动开启**（安装后默认停用）。

## 配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 生效范围 | 群聊与私聊 | 只想在群里用就选「仅群聊」 |
| 触发方式 | 粘贴链接即解析 | 改成「仅指令触发」后必须发「解析 + 链接」 |
| 指令触发词 | 解析,视频解析 | 仅指令模式下生效，中英文逗号都行 |
| 回复方式 | 发送视频 | 选「只发链接」则只回文本卡片，最省事也最稳 |
| 直发视频时长上限 | 不限 | **0 或留空 = 不限时长**，填了才按上限拦截 |
| 图文作品发送张数 | 3 张 | 图文作品最多发 9 张 |
| 同一链接重复解析冷却 | 15 秒 | 同群重复贴同一条链接会被忽略；0 或留空取默认，-1 关闭 |
| 解析结果缓存时间 | 600 秒 | 同一条链接在别的群被贴时直接复用结果；0 或留空取默认，-1 关闭 |
| 抖音 Cookie | 空 | 触发风控、老是解析失败时填 |
| B站 Cookie | 空 | 用于解锁更高清晰度，游客态一般已够用 |
| 小红书 Cookie | 空 | **不填就无法解析小红书**，见下方说明 |

## 行为说明

- **抖音**：走 `iesdouyin` 分享页内嵌的 `window._ROUTER_DATA`。实测前两次请求只回不带数据的壳页面，插件会自动重试三次（空壳响应很快，重试几乎不增加耗时）。
- **B站**：`view` 接口取标题封面，`playurl` 用 `platform=html5&high_quality=1` 拿**单文件 mp4**（自带音轨），所以不需要 ffmpeg 合流，也不会下到哑视频。按 1080P → 720P → 480P → 360P 逐级降级。
- **小红书**：取笔记页内嵌的 `window.__INITIAL_STATE__`，视频读 `media.stream` 的 `masterUrl`，图文读 `imageList` 原图。页面把 JS 字面量 `undefined` 写进了这段状态，插件会先替换成 `null` 再解析。
- **短链**：宿主出网客户端不自动跟随跳转，插件逐跳读 `Location` 手工跟随，最多两跳（`v.douyin.com`、`b23.tv`、`xhslink.com`）。
- **回复结构**：描述卡片和视频分成**两条**消息发。之前把「视频段 + 文本段」塞进同一条消息，部分 NapCat 版本会直接丢掉文本段，表现就是只有视频、没有说明；拆开之后描述一定能看到。视频被 QQ 拒收时再补一条无水印直链，不会静默失败。
- **描述卡片长什么样**：

  ```
  【哔哩哔哩】这可能是今年最好看的城市纪录片
  @某UP主 · 时长 21:05 · 1080P · 第一集：起点
  播放 123.4万 · 弹幕 2.1万 · 点赞 8.6万 · 收藏 3.2万

  拍摄历时三个月，走过 12 座城市。
  ```

  抖音没有独立标题，文案首行当标题、整段当描述，卡片会自动去掉重复的那一行；正文超过 260 字按上限截断。图文作品把描述拼在图片后面一条发出。
- **为什么时长上限默认是不限**：宿主的数字型配置项默认值是 `0`，如果把它当成「上限 0 秒」，任何视频都会被判超限、只发链接。所以本插件把 `0` / 留空一律解释成「未填写」，按不限处理；冷却与缓存同理（显式关闭请填 `-1`）。
- **缓存**：同一条链接在缓存有效期内被任意群或私聊再次粘贴时，直接用上次的解析结果，不再请求平台。播放地址本身带有效期，所以默认只缓存 10 分钟。

### 小红书必须配 Cookie

小红书网页端**未登录一律被跳走**，实测笔记页：

- 不带 Cookie → `302` 到 `/404/sec_xxx?redirectPath=...`；
- 带一个无效 Cookie → `500`；
- 带有效 Cookie → 直接返回笔记页，状态里才有笔记详情与视频地址。

也就是说没有 Cookie 时不存在「降级解析」这条路，插件会直接回一条提示，告诉管理员去填 Cookie。填法：浏览器登录小红书 → 打开任意笔记 → 开发者工具 Network 里复制请求头的 `Cookie`（至少要含 `a1` 与 `web_session`）。

> 注意：这段解析只用构造的页面结构做过单元测试，**没有在真实笔记上跑通**（手上没有可用 Cookie）。配好 Cookie 后如果报「没有从笔记页取到数据」，把报错发我，我按实际结构调整。

## 部署注意

1. **宿主需要支持按需响应长度**：抖音分享页约 32KB，关键数据在第 3 万字符之后，而宿主默认只回 20000 字符。本插件会带 `max_chars=120000` 请求（小红书申请到上限 200000），需要宿主 `plugin_sdk.http_request` 与出网闸门支持该参数（本仓库已内置，上限 200000）。
2. **事件超时要放宽**：解析最坏情况是「短链跳转 + 三次分享页请求 + 发送视频」，建议在 `.env` 中设置 `PLUGIN_EVENT_TIMEOUT=30`，默认 10 秒在「解析 + 发送视频」时容易撞线并重启子进程。
3. **出网代理**：宿主的出网客户端会继承 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量。如果服务器上配了代理但国内站点走不通，抖音、B站都会超时，需要清掉这两个变量。

- 真机连测（2026-10-17）：
